# Portfolio history price provenance

Canonical history requires every non-Pionex spot holding to have a finite positive mark, a supported source/quality pair, and a numeric per-symbol fetch time no later than capture and no older than 15 minutes. Supported live sources use `PUBLIC_LIVE_FETCH`; `CoinGecko REST` may use `PUBLIC_FALLBACK_FETCH` when it is a newly received quote. Unsupported, stale, generic `FALLBACK`, and `POLICY_ASSUMPTION` qualities do not qualify. A supplied numeric provider observation time is checked separately; when the provider supplies none, it remains `null`. Local `fetchedAt`/`ts` is receipt time, never provider observation time. The global `livePriceMeta.fresh` flag cannot qualify a symbol.

The history runtime records fetched marks in `livePriceMeta.perSymbol` and the matching `livePrices[symbol]` entry; source, quality, numeric value, fetch time, and observation time must agree across both representations. Failed or partial fetches update attempt diagnostics only and leave retained marks and their provenance unchanged. Only the original R18 shape containing `price`, `source: 'BINANCE_SPOT'`, and numeric `ts` without explicit quality, observation, fetch-time, or per-symbol metadata receives legacy compatibility. R18 ticker-cache reuse carries the original local receipt time. Its fixed `$1` stable-token fallback is labeled `STABLE_VALUE_POLICY` / `POLICY_ASSUMPTION`; it remains a display valuation but cannot complete canonical history while that holding is required. The current app quote producer labels local receipt time as `fetchedAt`; Binance REST/WebSocket quotes use `PUBLIC_LIVE_FETCH`, while a newly received CoinGecko quote uses `PUBLIC_FALLBACK_FETCH`. `updatedAt` alone is not admission provenance. Other legacy marks, including price-only values, remain usable by existing valuation/rendering paths but have unknown history freshness until a supported producer supplies explicit fetch provenance.

History stores the bounded per-symbol marks, source, fetch/observation times, capture time, source quality, and fallback reason in the existing `source_status` JSON. No schema migration or historical rewrite is needed. Old rows without `spotPriceProvenance` are excluded from canonical history as unknown legacy provenance; they are not modified or declared corrupted. Incomplete new captures are returned with diagnostics but are never inserted as complete points.
