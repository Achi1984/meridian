# Fixed local check executor (source-only)

`execute_check(repo_root, expected_scope, timeout_seconds=30)` executes one catalog leaf: `node --test docs/autonomy/event-adapter/test/event-continuation-adapter.test.mjs`. The caller must explicitly provide a trusted checkout and exact repository/request/op/head/base/PR/CI pins. No event field selects a command. `REQUIRED_POLICY` exports the single required check and the SHA-256 of its canonical JSON argument vector.

The executor requires a clean Git checkout, matching HEAD distinct from base, an existing base commit that is an ancestor, no ignored/untracked files, no submodules or skip-worktree/assume-unchanged entries, before and after the process. It uses resolved Node/Git launchers, no shell, a minimal environment, no inherited credentials/NODE_OPTIONS, disabled global/system Git config and hooks/fsmonitor. Effective partial-clone/promisor configuration is rejected before object reads, with `GIT_NO_LAZY_FETCH=1` as defense against implicit fetching. Repository filter configuration is rejected before status inspection, and signal termination produces no v2 check row. It concurrently bounds both output streams and execution time, then kills the process group even if the direct child has exited. Invalid checkout, timeout or output overflow produces no successful evidence receipt.

A completed invocation returns the real exit code, UTC timestamps, stdout/stderr digests and a v2-compatible `check`. Its `evidenceSha256` hashes the canonical execution record including exact supplied scope. Output text is not returned. A nonzero exit produces a failed row. This module never invokes the full source verifier, so the leaf does not recursively invoke this executor.

Tests use explicitly synthetic local Git commits, including a staged copy of the actual sibling adapter test suite. A Git object identity proves local content binding, not GitHub origin, CI-run identity or test correctness. CI/request pins remain caller claims; all authentication/provenance/authority flags remain false. The trusted test code itself executes with local process privileges: this is not an untrusted-code sandbox or network isolation boundary. Callers must not supply unreviewed checkouts. No workflows, provisioning, live producer wiring, remote operations or activation are introduced.

The before/after checks detect observed checkout changes; they cannot detect a hostile concurrent writer changing and restoring files between observations. Exclusive trusted checkout ownership is a deployment prerequisite. The receipt is returned in memory, not durably stored by this module.
