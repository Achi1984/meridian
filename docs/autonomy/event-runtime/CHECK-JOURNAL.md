# Local check receipt journal

Source-only, explicit-call persistence for the fixed `check_executor` catalog. This module performs no check execution, model call, network request, scheduling or remote write. It is separate from the event inbox and never changes that store's schema.

Initialize a new database explicitly with `initialize(db)`. Existing paths are rejected; missing/corrupt databases and unsupported schema versions fail closed. No reset, pruning or migration is implemented. Call `reserve(db, scope, check_id, command_sha256)`, then `mark_started(db, reservation)` before invoking the executor. After an actual executor return, `complete(db, reservation, receipt)` atomically stores the validated receipt and releases the global lock. For an uncertain outcome call `mark_unknown(db, reservation)`. The wrapper owns this ordering; the journal cannot prove that arbitrary callers actually ran a check.

All methods returning a record use `{key, scope, checkId, commandSha256, fence, state, receipt}`. `recover(db, scope, check_id, command_sha256)` reads that record without execution; an unknown key raises `JournalError('NOT_FOUND')`. State is RESERVED, STARTED, COMPLETE or UNKNOWN. Non-COMPLETE records have null receipt. Duplicate reservation always fails, including after completion. RESERVED/STARTED crashes and UNKNOWN never expire or automatically retry. A global active lock also blocks different scopes until valid completion; UNKNOWN keeps the lock. No takeover or operator-reset API is provided.

Identity includes repository, request/op IDs, head/base, PR, exact CI run/attempt/workflow/head and fixed check ID/command digest. The module reuses the executor's scope validator and catalog constants. Receipts must match the exact executor schema: explicit exit code, status, scope, command, output digests, ordered UTC timestamps, matching check projection, evidence digest and false authority flags. The evidence hash is recomputed from the executor's original record excluding `check` and `evidenceSha256`. Failed receipts remain failed. Raw stdout/stderr, prose, credentials and additional fields are rejected.

A second stored digest binds canonical identity plus newline plus canonical receipt. Recovery rechecks the record and exact binding, not only the digest. Hashes provide integrity checks, not authentication: a malicious caller or database writer can fabricate internally consistent records. Listed timestamps and hashes alone do not prove execution or GitHub CI provenance. `durable:false` inside the original receipt remains unchanged; it denotes the executor's original claim, not absence of this local persistence operation.

This is one local SQLite file with same-host process locking, not a shared-host, distributed, Actions artifact or remote exactly-once guarantee. FULL synchronous transactions and explicit 4096-byte pages are used; maximum 1000 records, 1 MiB canonical binding/receipt data and 1024 pages (4 MiB main database). Journals and filesystem overhead are additional. Disk/hardware guarantees depend on the local filesystem. Protect the database and trusted caller; do not delete it to bypass consumed reservations. Place it outside a checkout whose cleanliness the executor verifies.

Run `python -I docs/autonomy/event-runtime/test_check_journal.py`. Tests use explicitly simulated receipts to exercise validation, failure preservation, atomic rollback, concurrent OS processes, crash-after-start and crash-after-commit recovery. They do not claim those simulated receipts represent executed checks. The separate wrapper suite covers actual fixed executor invocation and journal composition.

Every operation verifies the bounded whole-store state before and after mutation: unique fences, current meta fence equal to the maximum stored fence, and exactly one active key/fence iff an unresolved reservation exists. A cleared or contradictory lock therefore fails closed on recovery and reservation. This detects inconsistent storage; it does not protect against a malicious writer rewriting all mutually consistent records.
