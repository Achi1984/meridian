# Controlled publisher marker recovery: source candidate

This packet integrates the existing reviewed helpers into one bounded operation.
It is inert on import, has no CLI, scheduler, workflow or automatic caller, and
does not authorize an actual owner-runtime invocation. No live pins or recovery
approval are supplied here. Setup remains a separate owner-approved operation.

## Trusted invocation boundary

Only the lead's authenticated, concrete owner session may arrange a dedicated
short-lived isolated Linux CPython 3.14.2 process after approval of the exact
operation. Verify the wrapper **before importing it** against independently
reviewed source evidence. Its later self-hash cannot establish bootstrap trust.
The runtime, standard library, installed dependency environment, filesystem/mount
namespace and continuous exclusive owner/source-tree window remain trusted
external prerequisites. No new authentication system is introduced.

The launcher calls `run_approved_recovery(manifest, failed_manifest, scope,
reconcile_argv, window_check)` and must exit with its return code. Missing inputs
block. A process accepts only one call, including failed calls. Restarting is
not retry authorization. Numeric owner/comment IDs, hashes, argv flags, timestamps
and the callback are caller-supplied scope records, **not authentication**.
The lead must preserve the approved full scope and both manifests in its durable
operation record; the archive retains their digests and reference IDs only.

`scope` binds the fixed action `ARCHIVE_PUBLISHER_ATTEMPT_ONCE`, owner account ID,
unique operation/window IDs, a deadline at most five minutes away, the exact
current and historical manifests, approved marker identity, baseline bytes,
reconciliation arguments and approval/reconciliation references. The callback
confirms the externally maintained window at each boundary; it cannot create or
prove exclusivity. A false callback, expired scope, changed source or target ends
the attempt. Same-UID races remain outside that operational contract.

## Concrete operation

1. Verify the fixed eight source/lock files against the supplied independently
   reviewed manifest. Historical failed-attempt manifest contains the auto and
   password setup helpers plus requirements and lock; preserve it rather than
   constructing it from current files. No pinned values are generated by the
   wrapper. Exact verified helper bytes execute in fresh module namespaces;
   sibling loader hooks bind those modules instead of reopening their sources.
2. Open passwd's canonical owner directory through retained no-follow directory
   descriptors. Compare the fixed marker with the approved complete identity.
   Baseline content is separately pinned. The normal owner-path inspector keeps
   its read-only interface; the context API additionally retains descriptors.
3. Call the existing `reconcile.main(argv)` once. Its strict parser, Linux/isolation,
   environment/tracing/TTY/core restrictions and provider → supervised read-only
   DB → provider sequence remain in force. Existing CLI, CA and installed psycopg
   provenance checks remain intact. Require exactly the successful bounded status
   delivery and integer return code zero. This is an **in-process main return**,
   not evidence of an outer OS exit; the existing DB supervisor checks its child.
4. Recheck window, source hashes, baseline, canonical directory names and marker.
   In the dedicated single-thread process, temporarily set umask 077, invoke the
   existing retirement primitive at most once, then verify canonical reachability,
   archive identity, original marker inode/content, exact evidence JSON bytes,
   owner/modes, and absence of a new active marker. Restore the previous umask.
5. Close retained descriptors and deliver one bounded final status. Return zero
   only on confirmed final delivery of `OWNER_RECOVERY_ARCHIVED_NO_SETUP_AUTHORIZED`.
   The supervising lead must also observe zero process exit. Missing/partial final
   output, nonzero exit, interruption or failure requires read-only reconciliation;
   never infer retry permission, delete evidence, repair modes or switch algorithms.

The wrapper's fixed manifest covers repository helpers and dependency lock inputs,
not the entire interpreter/stdlib/installed dependency tree. Those must come from
the independently reviewed pinned runtime/environment. Trusted CLI and CA content
guards are reused, not replaced. Repeated hashes and descriptor checks narrow
exposure but are not a race-free guarantee against same-UID concurrent changes.
Reading can change filesystem access timestamps. No setup function is called.

## Offline acceptance evidence

Tests use only fresh synthetic owner roots, synthetic scope/manifests and fake
provider services while executing the verified reconciliation main and real
filesystem retirement path. They cover fail-closed defaults, wrong scope/source/
marker/baseline, all three reconciliation stages, invocation and status failures,
lost window, changed source, detached canonical/archive paths, evidence tampering,
restrictive umask, fsync/close/interruption and at-most-once behavior. They do not
prove authenticated approval, actual provider/DB state or a live recovery cycle.
